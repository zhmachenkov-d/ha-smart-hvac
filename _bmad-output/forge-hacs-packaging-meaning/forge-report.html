HACS packaging meaning for ha-smart-hvac

Forge outcome · 2026-10-02 · clarify → hardened

Outcome

“HACS packaging” for this project means: reshape the monorepo so repo-root apps/hvac/ is canonical, Exclusive Session reaches it via app_dir, ship a custom-repo publish surface from this repo once it is public — after history hygiene — and stop at custom-repo (not default store).

Locked decisions

  • Same monorepo dual layout (not extract/mirror).
  • Canonical Python: apps/hvac/; Exclusive Session adapts.
  • Bridge: app_dir → repo-root apps/ (not symlink).
  • House apps.yaml gitignored; commit apps.yaml.example only.
  • Publish surface: hacs.json, HACS Action, releases, stranger app_dir docs.
  • Vehicle: this repo made public; gated on history rewrite/filter.
  • Ceiling: public custom repository only.

Rejected

  • Packaging mirror / extract repo — one tree preferred.
  • Keep appdaemon/apps/hvac/ canonical with a HACS façade.
  • Symlink bridge — app_dir chosen instead.
  • Layout-only meaning — publish knobs included.
  • Accept house IDs forever in public git history.
  • hacs/default inclusion — out of scope.

Weak points that survived

  • app_dir puts house wiring under the HACS-shaped apps/ tree — hygiene depends on gitignore + example discipline.
  • History rewrite before public is operational risk (force-push / coordination) — accepted as a gate, not solved here.
  • Repo is private today; HACS installability is blocked until visibility + hygiene land.
