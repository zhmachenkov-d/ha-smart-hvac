Automate HACS releases

ha-smart-hvac · loose forge · 2026-10-03 · outcome HARDENED

Workspace: _bmad-output/forge-hacs-release-automation/

Outcome

Идея усилена до решения: автоматический release train на python-semantic-release после merge в main, с write-back версии/changelog, tag v*, GitHub Release без assets, и CI-gate на Conventional Commits (title + commits). Потолок HACS — custom repository.

Locked

  • PSR на main: bump + CHANGELOG.md write-back + tag v{version} + GitHub Release.
  • Бамп по стандарту Conventional Commits / PSR defaults.
  • Auth: отдельный token в secrets (есть ruleset branch-protection).
  • CI-gate: PR title и commits.
  • Источник версии: pyproject.toml; baseline v0.1.0.
  • HACS: published Release обязателен; binary assets не нужны.

Rejected

  • release-please (Release PR).
  • JS semantic-release / второй калькулятор версии (commitizen и т.п.).
  • «Только версия/чеклист» без Release CI.
  • Редкий ручной сигнал релиза сверх Conventional Commits.
  • Binary release assets.
  • Never из plan-hacs-publish (нет tag→Release CI; только agent gh release create) — снят для будущих релизов.

Weak points that survived

  • Bot push на main — исключение из human PRs-only; зависит от корректного token + ruleset.
  • Без зелёного CC-gate «кривой» merge даёт тихий no-op или неверный bump — gate обязателен, но инструмент gate ещё не выбран в forge.
  • CI сегодня только на pull_request; release workflow на main — новая поверхность, которую нужно добавить отдельно от lint/test.
