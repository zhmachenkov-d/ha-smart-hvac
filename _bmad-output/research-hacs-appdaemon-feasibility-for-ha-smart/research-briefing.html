Executive summary

Yes — as a HACS AppDaemon app, not as a HA custom integration, and not with the current layout as-is.

HACS has a first-class AppDaemon category verified. The blocker is structure: HACS needs apps/<name>/ at repo root; this repo nests under appdaemon/apps/hvac/. Ship a custom repository first; default-store inclusion is optional and slow medium.

Landscape & maturity

  • Dedicated AppDaemon publish path + template (ad-hacs) verified
  • Discovery opt-in — niche audience verified
  • 56 defaults; Action supports category: appdaemon verified

Integration & packaging

  • Root apps/APP_NAME/, one app only; root hacs.json with name; public GitHub + README/topics/description verified
  • Downloads into <config>/appdaemon/apps/* verified
  • Custom repo immediately; default list PR can take months unverified

Implementation reality

  • Peers keep apps/ at repo root (ControllerX pattern) verified
  • This repo: nested appdaemon/apps/, no hacs.json, house IDs in apps.yaml — packaging work required
  • HAOS users may need app_dir aligned to HACS path verified

Ecosystem health

Category still maintained; quieter than integrations. Custom repository avoids default backlog. No documented deprecation.

Recommendations

  1. Treat HACS AppDaemon packaging as feasible
  2. Do not publish as-is — reshape to root apps/hvac/
  3. Prefer AppDaemon packaging over rewriting as a HA integration
  4. Custom repository first; defer hacs/default
  5. Document app_dir for HAOS users
