Gate ωc on saturation

Forge outcome · 2026-10-17 · pressure-test → hardened

Workspace: _bmad-output/initiative-gate-omega-c-on-saturation/forge-gate-omega-c-on-saturation/

Outcome

Stop the soft-kill path where ωc ratchets up while Set Water Temperature is clamped, then sticks the blow-up latch. Use a directional commit gate with strict same-tick apply, decay ωc on latched ticks from real |u_track|, and skip redundant plant writes when the entity already holds the desired value.

Locked decisions

  • Success criterion A (anti soft-kill), not headroom-only adapt.
  • Directional clamp on commit; strict: no proposed ωc in with_omega_c when blocked.
  • Write-on-change inside _write_setpoint vs plant entity state; tick continues.
  • Latched recovery: step ωc down while |u_track| > 0.8 · u_track_max (or non-finite).
  • ADR/docs speak to the failure mode, not “only when can actuate” philosophy.

Rejected

  • Full freeze of ωc commit on any SWT clamp.
  • |ωc·e/b0| as gate or decay criterion (blind to z₂ while latched).
  • Persistence-only gate with proposed ωc still applied each tick.
  • Skip write via early-return (would stall ESO/tick).
  • Last-written cache as equality baseline.
  • R1-only edge decay; R3 hard reset to config ωc; one-shot safe-ωc jump.

Weak points that survived

  • 0.8 margin is a chosen clearance from the guard ceiling, not derived from plant ID.
  • Stepped decay at max_rate_fraction can leave the loop in FF-only for several ticks after a deep overshoot of ωc.
  • Ops reset of ladrc_tune_state.json remains a last resort if something outside this model poisons state.
