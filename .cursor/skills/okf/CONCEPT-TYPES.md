# OKF concept types — producer conventions

This project uses four OKF types inside `knowledge/`. Every typed page is one `.md` file
with YAML frontmatter; `type` is required.

## Shared rules

| Rule | Detail |
|------|--------|
| Links | Bundle-relative: `/concepts/foo.md`, `/decisions/bar.md` |
| Timestamps | ISO 8601 UTC (`2026-07-08T08:00:00Z`); bump on substantive edits |
| One idea per file | Split when a page covers multiple independent concepts |
| Citations | End with `# Citations` section pointing to references or raw paths |
| Glossary | Short definitions → `CONTEXT.md`; depth stays in concepts |
| ADRs | Irreversible decisions → `docs/adr/` **and** a lightweight `decisions/` page |

### Required frontmatter

```yaml
---
type: Concept          # Concept | Decision | Reference | Playbook
title: Human title
description: One-line summary for indexes
tags: [tag1, tag2]
timestamp: 2026-07-08T08:00:00Z
---
```

References also require `resource:` pointing at the raw source path (directory or file).

---

## Concept (`type: Concept`)

**When:** Domain entity — protocol detail, hardware constraint, mapping unit, cluster attribute.

**Location:** `knowledge/concepts/`

**Body sections (typical):**

- Opening paragraph — what it is and how this project uses it
- `##` subsections for behaviour, encoding, constraints
- Cross-links to related concepts, decisions, playbooks
- `# Citations` at end

**Create vs update:**

- **Create** when a term appears in prose and agents would benefit from a dedicated page
- **Update** when refining encoding, pins, or mapping — bump `timestamp`

---

## Decision (`type: Decision`)

**When:** Trade-off or architectural choice with rationale (even before a formal ADR exists).

**Location:** `knowledge/decisions/`

**Body sections:**

- `## Decision` — the choice in one paragraph
- `## Rationale` — why
- `## Formal ADR` — link to `docs/adr/NNNN-*.md` when filed
- `## Consequences` — what follows for firmware and ops

**Create vs update:**

- **Create** when two approaches were considered and one was chosen
- **Update** when consequences become clearer; file ADR when decision is irreversible

---

## Reference (`type: Reference`)

**When:** Binding to an external spec or immutable raw source.

**Location:** `knowledge/references/`

**Extra frontmatter:** `resource: raw/opentherm/` (or specific file)

**Body sections:**

- `## Status` — stub vs ingested
- `## Key sections` — what to pull on next ingest
- `## Linked concepts` — back-links

**Create vs update:**

- **Create** once per authoritative source
- **Update** status and linked concepts after each ingest pass

---

## Playbook (`type: Playbook`)

**When:** Repeatable workflow — ingest, lint, mapping maintenance, bring-up checklist.

**Location:** `knowledge/playbooks/`

**Body sections:**

- Numbered steps an agent or human can follow
- Shell commands for scripts where applicable
- Links to concepts/decisions the workflow touches

**Create vs update:**

- **Create** for new operational workflows
- **Update** when tooling or paths change

---

## Reserved files

| File | Role |
|------|------|
| `knowledge/index.md` | Root catalog; declares `okf_version: "0.1"` |
| `knowledge/log.md` | Append-only change history |
| `knowledge/*/index.md` | Auto-generated by `regen_index.py` |

Do not hand-edit type indexes — regenerate after concept changes.
